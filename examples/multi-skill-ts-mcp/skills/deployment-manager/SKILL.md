# Deployment Manager

帮助用户管理应用部署全流程，从发布计划到上线验证。

## 部署流程

1. **发布准备**：确认发布内容、变更范围、依赖关系
2. **制定计划**：选择部署策略（蓝绿/金丝雀/滚动）、时间窗口、检查清单
3. **执行部署**：生成部署脚本或调用 MCP 工具执行部署
4. **验证上线**：健康检查、功能验证、性能监控
5. **应急预案**：回滚方案、故障处理流程

## 部署策略选择

| 策略 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| 蓝绿部署 | 关键业务、零停机要求 | 零停机、快速回滚 | 资源翻倍 |
| 金丝雀发布 | 渐进式发布、风险控制 | 风险可控、逐步验证 | 复杂度高、时间长 |
| 滚动更新 | 无状态服务、资源有限 | 资源效率高 | 有短暂停机风险 |
| 重建部署 | 开发环境、非关键应用 | 简单直接 | 有停机时间 |

## 发布检查清单

- [ ] 代码已合并到主分支
- [ ] 所有测试通过
- [ ] 数据库迁移脚本已准备
- [ ] 配置文件已更新
- [ ] 回滚方案已制定
- [ ] 监控告警已配置
- [ ] 相关人员已通知
- [ ] 发布时间窗口已确认

## 与 MCP 服务器协作

当需要以下操作时，调用 `devops-tools` MCP 服务器：
- 查询部署历史
- 触发部署
- 查询服务健康状态
- 获取部署日志

## 回滚方案模板

```
## 回滚方案

### 触发条件
- 错误率超过 X%
- 响应时间超过 Xms
- 核心功能不可用

### 回滚步骤
1. 停止新版本流量
2. 切换到旧版本
3. 验证旧版本功能
4. 通知相关人员

### 回滚验证
- 健康检查通过
- 核心功能正常
- 错误率恢复正常
```
