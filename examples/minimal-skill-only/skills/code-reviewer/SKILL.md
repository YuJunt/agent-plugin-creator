# Code Reviewer

对代码变更进行系统性审查，确保代码质量、安全性和可维护性。

## 审查流程

1. **理解变更**：阅读 diff 或代码文件，理解变更目的和范围
2. **检查清单**：按以下维度逐项审查
3. **输出报告**：按严重程度分类，给出具体建议

## 审查维度

| 维度 | 检查点 |
|------|--------|
| 正确性 | 逻辑是否正确？边界条件是否处理？错误处理是否完善？ |
| 安全性 | 是否有注入风险？敏感信息是否泄露？权限控制是否到位？ |
| 性能 | 是否有明显的性能问题？时间/空间复杂度是否合理？ |
| 可读性 | 命名是否清晰？注释是否充分？结构是否易于理解？ |
| 可维护性 | 是否有重复代码？是否符合 SOLID 原则？测试是否覆盖？ |
| 最佳实践 | 是否符合语言/框架最佳实践？是否有过时的 API？ |

## 输出格式

```
## 代码审查报告

### 🔴 严重问题（必须修复）
- [文件:行号] 问题描述
  - 建议：修复建议

### 🟡 中等问题（建议修复）
- [文件:行号] 问题描述
  - 建议：修复建议

### 🔵 轻微问题（可选优化）
- [文件:行号] 问题描述
  - 建议：优化建议

### ✅ 做得好的地方
- 亮点描述
```

## 使用示例

用户："帮我审查这个 PR 的代码变更"
1. 读取 PR diff
2. 按审查维度逐项检查
3. 输出审查报告

用户："这个函数有什么问题吗？"
1. 读取函数代码
2. 重点检查正确性和安全性
3. 给出具体问题和建议
