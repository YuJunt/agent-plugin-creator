# Knowledge Assistant

基于向量检索的知识库问答系统，支持文档入库、语义检索、智能问答。

## 工作流程

1. **文档入库**：用 MCP 工具 `add_document` 将文档（PDF/TXT/Markdown）分块并向量化存入知识库
2. **索引管理**：用 `list_documents` 查看已入库文档，用 `delete_document` 删除不需要的文档
3. **语义检索**：用 `search` 根据用户问题检索最相关的文档片段（Top-K）
4. **上下文构建**：将检索到的片段拼接成上下文，注意不超过 token 限制
5. **智能问答**：基于检索到的上下文回答用户问题，引用来源文档
6. **追问处理**：支持多轮追问，用 `search` 补充检索相关信息

## 关键规则

- 回答必须基于检索到的上下文，不要编造信息
- 每个回答必须引用来源（文档名+片段编号）
- 检索不到相关信息时，明确告知用户"知识库中没有相关信息"
- 文档入库前必须检查格式，不支持的格式先转换
- 大文档（>50页）自动分块，块大小 512 token，重叠 50 token

## Gotchas

### 坑 1：检索结果不相关
- **症状**：检索到的文档片段和用户问题无关
- **修正**：调整 `search --top-k 10` 增加返回数量，或用 `search --score-threshold 0.7` 提高相似度阈值
- **原因**：嵌入模型对短查询理解不足，或文档分块不合理

### 坑 2：回答超出上下文长度
- **症状**：拼接的上下文超过模型 token 限制
- **修正**：减少 `--top-k` 到 3-5，或对检索结果先做摘要再拼接
- **原因**：每个文档片段约 500 token，5 个片段就是 2500 token，加上问题和系统提示容易超限

### 坑 3：文档入库失败
- **症状**：PDF 文档入库报错或内容乱码
- **修正**：先用 `pdftotext` 转换为纯文本再入库，或检查 PDF 是否为扫描件（需要 OCR）
- **原因**：复杂排版的 PDF 直接提取文本可能丢失格式或乱码，扫描件没有文本层
